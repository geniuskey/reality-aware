# Honest Scope

This page exists so the rest of the site can be read literally. Anything NANO has not demonstrated is
listed here rather than implied elsewhere.

## Limitations

### The prior is synthetic, not physical

The biased prior is generated by distorting the WM-811K wafer map itself: radial bias, smoothing, and
a global offset and gain. There is no TCAD, CAE or RCWA simulation anywhere in the pipeline. Real
simulation error has structure this distortion does not reproduce — mesh artifacts, calibration drift
between recipes, systematically wrong physics in specific regimes. Results here transfer as an
argument about the *method*, not as a prediction of accuracy on real simulation output.

### WM-811K labels are not metrology values

Wafer maps are binary pass/fail per die. Real metrology produces continuous, noisy readings — CD,
thickness, overlay — with tool-dependent measurement error. A continuous target changes the
estimator's job and would change the uncertainty model with it. Nothing here shows that the same
selection rule ranks locations well on continuous data.

### Uncertainty is used, not claimed to be calibrated

NANO computes an uncertainty map and ranks locations by it. It does **not** claim that the map is
calibrated — that a stated interval covers the truth at the stated rate. Ranking can be useful while
calibration is poor, and calibration has not been evaluated here. Any use of these uncertainty values
as probabilities would be unsupported.

### Every measurement costs the same

The budget counts measurements, and one die costs one unit regardless of where it is. Real
measurement cost depends on stage movement, recipe changes, tool availability and queue position. A
selection rule that ignores cost can pick an expensive route that a cost-aware rule would beat on
wall-clock time even while losing on measurement count.

### Accessibility and scheduling are out of scope

Whether a die *can* be measured next — tool assignment, wafer handling, lot priority, scheduling
windows — is not modelled at all. The prototype assumes any unmeasured die is immediately available.

### One wafer at a time, no cross-wafer learning

Each episode is independent. Nothing learned on one wafer transfers to the next, and no lot-level or
tool-level structure is exploited. This isolates the selection rule cleanly, and it also forgoes a
source of information a production system would certainly use.

### The evidence base is small

The published configuration covers a modest number of wafers and seeds, recorded in
`results/benchmark_summary.json` and printed under every table on this site. It is enough to compare
selection rules under identical conditions. It is not a fab-scale validation, and the
[benchmark page](./benchmark) reports the spread rather than the mean alone for exactly that reason.

## What the prototype does establish

- A measurement-selection loop can be built so that reality is reachable only through one
  budget-accounting tool, which makes the comparison against baselines auditable.
- Prediction, uncertainty and prior-disagreement can be produced as separate inspectable maps rather
  than collapsed into a single score.
- Under a fixed budget, identical initial observations and identical wafers, acquisition-driven
  selection can be compared to Random and Grid fairly — and the result, favourable or not, is
  reproducible from a seed.

## Where this goes next

Clearly separated from what is demonstrated above — these are directions, not results.

| Direction | What it would add |
| --- | --- |
| **SECOM dataset** | Feature missingness rather than spatial sparsity. The unknown becomes *which measurement channel* to acquire, not only where. |
| **SEM / TEM field-of-view selection** | Selecting an imaging location and magnification, where the cost per observation is large and the field of view is tiny. |
| **Real simulator integration** | Replacing the synthetic prior with TCAD, CAE or RCWA output, so the Sim2Real gap being closed is a real one. |
| **Wafer / lot / tool hierarchy with provenance** | Sharing information across wafers while tracking where each value came from, so a correction can be attributed. |
| **Heterogeneous measurement cost** | An acquisition function scoring value per unit of cost instead of value per measurement, which is the version a fab would actually deploy. |
| **Uncertainty calibration** | Evaluating coverage properly, so uncertainty could be used as a probability rather than a ranking. |

## How to read this site

- A number is only real if it came from `results/benchmark_summary.json`. If the file is absent, the
  site says *Run benchmark to generate results* rather than showing an example value.
- Diagrams labelled <span class="nano-tag" data-kind="conceptual">Conceptual illustration</span> are
  drawn from formulas written to explain the mechanism. They are not data.
- Ground truth is marked <span class="nano-tag" data-kind="hidden">Hidden from agent</span> wherever
  it appears, because the agent's not seeing it is the entire premise.
- Pages describing structure that is not yet implemented say so at the top, in a warning block.

No confidential, internal or proprietary data, terminology or product name appears anywhere on this
site or in this repository.
